---
title: Sharing a card
description: The link forms, the Nimiq Pay deep link, and the memo that makes a payment a stamp.
---

A card is a short code. Everything else is a way of carrying that code to a customer's
phone.

## The code

```text
5FQQ2J56
```

Eight characters, upper case, from a thirty character alphabet with the look-alikes and the
vowels taken out: no I, L, O or U, because they read as 1, 1, 0 and V, and no A or E, so a
code can never spell a word a merchant would rather not print on their counter. A customer can type it into Vango and get straight to the card page. Read it out over
a counter and it survives the journey, which a URL does not.

## The link forms

| Form | Looks like | Use it for |
|---|---|---|
| Card link | `https://vango.app/app/c/5FQQ2J56` | Anywhere a customer can tap: your bio, a WhatsApp message, a printed QR |
| Pay deep link | `https://nimpay.app/miniapps/open/vango.app` | Opening Vango inside Nimiq Pay from outside it |
| Pay deep link, scheme form | `nimiqpay://miniapp?url=vango.app/app/c/5FQQ2J56` | The same thing with the card in it, for a native context that handles custom schemes |
| Code only | `5FQQ2J56` | Speaking, printing, or a sign on the wall |

Two things about the deep link that are easy to get wrong:

- **Pay's Custom URL field keeps the domain.** Type a full card link into it and the root of
  the domain is what loads, so a customer who lands on the home screen can type the code.
  A card link opened from inside Pay, or a deep link carrying the path, goes straight to
  the card page.
- **HTTPS only.** The wallet and the camera both need a secure context. A plain `http://`
  address will open and then quietly do nothing useful.

## The QR code

The card page renders its own QR of the card link, as an SVG, so it prints cleanly at any
size. Tape it next to the till. A customer scans it with their phone camera, Pay opens Vango,
and they are on the card page.

Vango uses the camera the other way too, on the merchant's redeem screen. Inside the Pay web
view on iOS that works over HTTPS and nowhere else, which is the same secure-context rule as
above.

## The memo

This is the one string that has to be exact:

```text
vango:5FQQ2J56
```

Vango puts it into the payment for you, so a customer following the normal flow never types
it. Case does not matter, because some keyboards capitalise the first letter on their own. If
somebody pays by hand from Pay, the memo has to match the card, the amount has to be
at least the card's minimum, and the recipient has to be the card's receiving address.
Otherwise the payment is just a payment: it arrives in the merchant's wallet, and the stamp
engine refuses it with a plain reason, such as `memo not vango` or `below minimum`.

The memo costs nothing. We measured it on testnet: a 1 NIM payment carrying a Vango memo paid
a fee of zero.
