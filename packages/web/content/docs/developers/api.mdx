title: API reference
description: Every Vango route with its auth, request body, response and errors.

One JSON API, served by Fastify. Every route is listed here with what it takes, what it gives
back, and how it fails.

## Conventions

- **Base URL.** The same origin that serves the mini app, for example `http://localhost:8787`
  in development.
- **Auth.** Routes marked "session" need `Authorization: Bearer vs1...`, the token from
  `POST /api/auth/verify`. Routes marked "owner" need a session that owns the card in
  question. A missing or unknown token gives `401 {"error":"not signed in"}`.
- **Every failure has the same shape:** `{"error":"words a client can show a person"}`. A 500
  always says `something went wrong`, and the detail goes to the server log, never to the
  caller.
- **Amounts are Luna**, the smallest unit of NIM. 1 NIM is 100000 Luna, and `minLuna` is never
  below 100000.
- **Rate limits, counted by IP, per minute:** 60 globally, 10 on the auth routes, 20 on the
  redeem routes. Over the limit gives `429 {"error":"too many requests, wait a minute"}`.
- **Times.** `expiresAt` is milliseconds since the epoch on the challenge routes and an ISO
  string on the redemption routes, because one comes from a signed message and the other from a
  database row.

## Auth

### POST /api/auth/challenge

No auth, no body needed. Returns the message the wallet has to sign.

```json
{
  "message": "vango-login:4f2c9ab1e5d0742c8b1a6f3e9c0d5817:1789119232753",
  "nonce": "4f2c9ab1e5d0742c8b1a6f3e9c0d5817",
  "expiresAt": 1789119232753
}
```

The nonce is single use and lives ten minutes.

### POST /api/auth/verify

No auth. Turns a signature into a session.

```json
{
  "message": "vango-login:4f2c9ab1e5d0742c8b1a6f3e9c0d5817:1789119232753",
  "publicKey": "hex, 32 bytes",
  "signature": "hex, 64 bytes",
  "visibleAddress": "NQ66 KBKY VKLD 6J8H N23B Y7MV PCT2 7X2D K54R",
  "remoteAddress": "NQ54 92V5 S1C3 EAJF HVE6 B2KB 8U31 6D3D VUMC",
  "language": "en",
  "fiat": "USD"
}
```

`remoteAddress` is optional, but you want to send it. It is `listAccounts()[1]`, the address
that shows up as the sender of this wallet's payments, and without it stamps cannot be matched
to this user. Any stamps already on the chain for these addresses are attached to the user at
this moment, and the count comes back in the server log as `attachedStamps`.

Returns `200`:

```json
{
  "token": "vs1.<32 random bytes as hex>",
  "user": { "id": "uuid", "visibleAddress": "NQ...", "remoteAddress": "NQ..." }
}
```

Errors: `400 message is not a vango login challenge`, `400 visible address is not a Nimiq
address`, `401 nonce unknown`, `401 nonce used`, `401 nonce expired`, `401` with the
verification reason when the public key does not derive to the claimed address, and `409 that
remote account belongs to another wallet`.

### GET /api/me

Session. Everything the app needs to draw itself in one call.

```json
{
  "user": { "id": "uuid", "visibleAddress": "NQ...", "remoteAddress": "NQ..." },
  "owned": ["CardSummary, the shape under POST /api/cards"],
  "held": ["HeldCard, the shape under GET /api/wallet"]
}
```

## Cards

### POST /api/cards

Session. Opens a card. The body is strict: an unknown field is refused rather than quietly
ignored, so a client written against an older shape hears about it instead of believing the card
pays into an address it named.

```json
{
  "name": "Vango Demo Cafe",
  "rewardKind": "nth_free",
  "rewardText": "Free coffee on visit 3",
  "targetVisits": 3,
  "minLuna": 100000
}
```

| Field | Rule |
|---|---|
| `name` | 1 to 40 characters |
| `rewardKind` | `nth_free` or `cashback` |
| `rewardText` | 1 to 60 characters, the merchant's own words |
| `targetVisits` | 2 to 20, required for `nth_free` |
| `cashbackBps` | 1 to 2000 basis points, that is 0.01 to 20 percent, required for `cashback` |
| `minLuna` | optional, at least 100000 |

There is no receiving address field. A card always receives at the merchant's own visible
address, read from their user row.

Returns `201` with the card summary:

```json
{
  "code": "5FQQ2J56",
  "name": "Vango Demo Cafe",
  "rewardKind": "nth_free",
  "rewardText": "Free coffee on visit 3",
  "targetVisits": 3,
  "cashbackBps": null,
  "minLuna": 100000,
  "receivingAddress": "NQ63NLNX4H6RM3R4XB928Y1X5GTSJUGC5QFJ",
  "active": true,
  "stampCount": 12,
  "customerCount": 5,
  "createdAt": "2026-09-12T05:46:07.014Z"
}
```

`customerCount` counts distinct paying addresses, because a customer who never opened the app
still walked through the door.

Errors: `400` naming the first thing wrong, plus `400 targetVisits is required for an nth_free
card` and `400 cashbackBps is required for a cashback card`.

### GET /api/cards/:code

No auth, because a customer reads this before they have signed in.

```json
{
  "code": "5FQQ2J56",
  "name": "Vango Demo Cafe",
  "rewardKind": "nth_free",
  "rewardText": "Free coffee on visit 3",
  "targetVisits": 3,
  "cashbackBps": null,
  "minLuna": 100000,
  "receivingAddress": "NQ63NLNX4H6RM3R4XB928Y1X5GTSJUGC5QFJ",
  "memo": "vango:5FQQ2J56",
  "active": true
}
```

Errors: `404 unknown card`, which is also the answer for a badly shaped code.

### PATCH /api/cards/:code

Owner. Pauses or resumes a card. A paused card takes no new stamps and the watcher stops
following its address.

```json
{ "active": false }
```

Returns the card summary. Errors: `403 this card belongs to another merchant`, `404 unknown
card`.

## Stamps

### POST /api/stamps/claim

Session. The two-second path: the phone has a transaction hash, and the server fetches that
transaction from the chain itself before deciding anything.

```json
{ "hash": "e37dde859da8f0e451769d7afba8a732e7e906f434d6afc9e55d409aa5940a08" }
```

Returns `200` whether or not it stamped, because "we looked and it does not count" is an answer,
not a failure:

```json
{
  "result": { "stamped": true, "stampId": "uuid", "cardCode": "5FQQ2J56", "blockNumber": 11222943 },
  "progress": {
    "rewardKind": "nth_free",
    "stamps": 1,
    "target": 3,
    "redeemable": false,
    "totalLuna": 100000,
    "cashbackLuna": 0
  }
}
```

When it does not stamp, `result` is `{"stamped": false, "reason": "..."}` with one of these
reasons: `not included`, `no memo`, `memo not vango`, `unknown card`, `card inactive`,
`wrong recipient`, `below minimum`, `sender is merchant`, `already stamped`.

`blockNumber` is the block the payment was included in, which the card shows under the new stamp. `progress` is present only when the payment came from an address this session owns. Anybody may
report any hash, including a stranger's: the stamp is still written, it simply is not theirs, so
no progress comes back with it.

Errors: `400 hash: not a transaction hash`.

## Wallet

### GET /api/wallet

Session. Every card this wallet has ever been stamped on, sorted by name.

```json
{
  "held": [
    {
      "code": "5FQQ2J56",
      "name": "Vango Demo Cafe",
      "rewardText": "Free coffee on visit 3",
      "rewardKind": "nth_free",
      "progress": {
        "rewardKind": "nth_free",
        "stamps": 3,
        "target": 3,
        "redeemable": true,
        "totalLuna": 300000,
        "cashbackLuna": 0
      }
    }
  ]
}
```

A card stays in the list after its reward is taken, because the next visit starts it again.

## Redeem

### POST /api/redeem/start

Session. Asks for the message to sign for one card.

```json
{ "code": "5FQQ2J56" }
```

Returns `200`:

```json
{
  "message": "vango-redeem:5FQQ2J56:9b1c4e77d2a04f118ab3:1789119832753",
  "nonce": "9b1c4e77d2a04f118ab3",
  "expiresAt": 1789119832753,
  "reward": { "kind": "nth_free", "text": "Free coffee on visit 3", "stampsToConsume": 3 }
}
```

On a cashback card the reward carries `cashbackLuna` instead of `stampsToConsume`.

Errors: `409 not redeemable yet`, which comes with the current `progress` so the app can show
"one of three" without a second call, and `404` for an unknown card.

### POST /api/redeem/sign

Session. The signed message in, the reward out.

```json
{
  "message": "vango-redeem:5FQQ2J56:9b1c4e77d2a04f118ab3:1789119832753",
  "publicKey": "hex",
  "signature": "hex"
}
```

Returns `200`:

```json
{
  "token": "the secret the QR carries",
  "code6": "418207",
  "expiresAt": "2026-09-12T06:04:03.221Z",
  "reward": { "kind": "nth_free", "text": "Free coffee on visit 3", "stampsToConsume": 3 }
}
```

The token is stored hashed and never written to a log. Both it and the six digits are good for
ten minutes.

Errors: `401` on a bad or replayed signature, `409 not redeemable yet` with progress attached.

### GET /api/redeem/:tokenOrCode

Owner. The merchant's read, by scanned token or by typed six digits.

```json
{
  "status": "pending",
  "cardName": "Vango Demo Cafe",
  "rewardText": "Free coffee on visit 3",
  "rewardKind": "nth_free",
  "customer": "NQ66 KBKY ... K54R",
  "stampsConsumed": 3,
  "cashbackLuna": 0,
  "expiresAt": "2026-09-12T06:04:03.221Z"
}
```

`status` is `pending`, `confirmed` or `cancelled`, worked out at read time so an expired reward
never reads as pending. `customer` is masked.

Errors: `404 reward not found`, which is what a stranger gets even for a real token belonging to
another merchant. Six-digit codes only resolve among that one merchant's live pending rewards.

### POST /api/redeem/:token/confirm

Owner. The reward was handed over. No body.

On a stamp card the answer is `{"status":"confirmed"}`. On a cashback card it also says exactly
what to pay:

```json
{
  "status": "confirmed",
  "payTo": "NQ66 KBKY VKLD 6J8H N23B Y7MV PCT2 7X2D K54R",
  "amountLuna": 20000,
  "memo": "vango-cashback:418207"
}
```

Errors: `409 this reward was already given`, `409 this reward expired before it was confirmed`,
`404 reward not found`. The write carries the whole check in its condition, so two taps on
Confirm produce one row between them.

### POST /api/redeem/:token/paid

Owner. Settles the cashback by transaction hash.

```json
{ "hash": "cf1ca7c9be545760ba724bc3da80b5b774a36a6a3d74930dbbbe7f61126cf70f" }
```

Returns `{"status":"confirmed","cashbackTxHash":"cf1ca7..."}`.

The server fetches that transaction and requires all of it: included in a block, recipient is
the customer, value at least the amount owed, sender is the merchant. One hash settles at most
one reward.

Errors: `409 payment did not come from the merchant`, `400 hash: not a transaction hash`.
